# 전달 대상 등록·조회

사용자 요청: Spring 기초에 해당하는 등록·조회 구현은 에이전트가 진행한다.

## 구현

- Endpoint record, Controller, Service, 메모리 Repository.
- 프로젝트 1에서 POST/GET `/api/projects/1/endpoints` 지원.
- 이름·HTTPS URL·이벤트 유형 검증, 활성 상태 기본 true.
- 등록 개수는 프로젝트당 10개. 메모리 실습에서는 개수 확인과 저장을 같은 서비스 잠금으로 보호한다.
- 목록은 생성 순서의 수정 불가능한 복사본이다.

## 검증

API 테스트를 먼저 실행해 미구현 경로의 실패를 확인했다.
구현 후 `./scripts/backend.sh test assemble` 성공, 테스트 12개 통과.
등록·빈 목록·조회·공백 이름 정리·잘못된 JSON과 URL·누락 입력·이름 길이·프로젝트 경계·중복 등록·개수 한도를 검증했다.
실제 포트에서 서버를 켜는 HTTP 확인과 동시 부하 시험은 수행하지 않았다. pi 실행·PASS 기록은 사용하지 않았다.

## 한계와 다음 학습

재시작 시 데이터 소실. 실습 프로젝트 1만 존재하며 인증은 없다.
URL 검사 범위는 형식뿐이며 목적지 허용 목록·소유 확인·DNS 검증은 실제 전송 및 공개 데모 단계에서 필요하다.
서명키 발급, 수정·중지, 실제 HTTP 전송은 이번 작업 범위 밖이다. 최종 명세 F-03 전체 완료를 뜻하지 않는다.

다음 학습은 PostgreSQL 테이블·제약조건을 설계하고 이 저장소를 교체하는 것이다.
특히 메모리 잠금이 프로세스 여러 개에서는 왜 충분하지 않은지, 10개 제한을 DB에서 어떻게 지킬지 살펴본다.
