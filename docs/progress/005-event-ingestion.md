# 005 — 이벤트 접수

기록일: 2026-11-10. 사용자 요청에 따라 명세 F-04의 저장·중복 처리 부분을 구현했다. 인증이 없는 로컬 프로젝트 1 실습 단계이며 최종 F-04 전체 완료는 아니다.

## 변경

- V2로 events·deliveries를 추가. 이벤트는 발생한 사실, delivery는 대상별 전달 대기다. 실제 전송 시도인 attempt는 아직 만들지 않았다.
- POST /v1/events: 신규 202, 동일 입력 중복 200, 동일 외부 ID의 내용 충돌 409.
- EventRequest: 최대 64 KiB, 최상위 필드·타입·길이, 중복 JSON 키와 비표준 숫자 검증.
- 정확한 숫자를 위해 BigInteger/BigDecimal로 파싱하고 PostgreSQL JSONB로 동등성을 비교한다. 저장 불가능한 NUL·Unicode·숫자 범위는 사전 거절한다.
- EventService의 트랜잭션에서 기존 프로젝트 잠금 → 중복 확인 → 10000개 한도 → 이벤트 저장 → 대상별 전달 저장을 수행한다.
- UNIQUE(project_id,event_id)는 DB의 최종 중복 방어선이다. 서비스는 잠금으로 경쟁 요청을 순서대로 처리해 충돌 예외를 제어 흐름으로 사용하지 않는다.
- INSERT SELECT 한 문장으로 활성·동일 유형·동일 프로젝트 대상을 선택하고 URL·전체 송신 payload를 고정한다.
- 최초 matched_delivery_count를 저장하므로 중복 요청 시 대상 설정이 변해도 원래 응답을 반환한다.
- 저장 실패 시 이벤트도 롤백. 오류 응답은 code/message/traceId, 저장 실패 로그에는 대응 traceId만 기록한다.

## 검증

미구현 POST 경로에 대해 테스트가 실패하는 것을 먼저 확인했다.
구현 후 이벤트 API 31개, 기존 endpoint API 14개, 마이그레이션 2개로 총 47개 통과. `test assemble` 성공.

- 동일 요청 100개 동시 접수: 202 하나·200 99개, 이벤트 하나·대상별 전달 한 개.
- 전달 테이블에 실패 제약을 주입: 이벤트·전달 모두 롤백, 503.
- 대상 변경 후 중복 요청: 추가 매칭 없음, 원래 URL·대상 수 유지.
- 활성·유형 대소문자·프로젝트별 매칭, 대상 없음 접수.
- 객체 키 순서·1/1.0 동등, 큰 정수 차이·배열 순서·자료형·type 차이 충돌.
- 잘못된 JSON·누락/미정의 필드·중복 키·숫자 범위·NUL 거절, UTF-8 65536바이트 허용 및 초과 거절.
- 이벤트 10000개에서도 동일 요청 조회 허용, 신규 거절. 다른 프로젝트의 같은 외부 ID와 독립.
- 빈 DB V1→V2, 기존 V1 baseline DB의 V2 업그레이드와 기존 데이터 보존.

로컬 실행 JAR로 V2를 적용했다. 기존 endpoint 전체 데이터를 적용 전후 비교해 보존을 확인했다.
실제 포트에서 목록 GET 200, 잘못된 이벤트 POST 400을 확인했다. 로컬 events·deliveries는 0건으로 유지했고 임시 앱은 종료했다.
구현 커밋 `183b873`을 push한 뒤 [GitHub CI의 PostgreSQL 테스트·빌드 성공](https://github.com/Dalzoo03/flowhook/actions/runs/42768671610)을 확인했다.

초기 마이그레이션 테스트는 info().all()의 첫 항목을 BASELINE으로 가정해 실패했다. 이 목록에는 적용하지 않은 V1 SQL 메타데이터도 포함될 수 있어, 버전 1 BASELINE 기록의 존재와 V2 적용 결과를 명시적으로 검증하도록 수정했다.

## 제한

인증 없음, 프로젝트 1 고정. 실제 전송·attempt·worker·재시도·조회 API는 없다.
현재는 프로젝트별 접수를 직렬화하므로 부하 증가 시 병목이 될 수 있다. 데이터 한도 10000개에서 먼저 정확성을 학습하고 이후 측정한다.
모든 쓰기가 같은 잠금 규칙을 따라야 한다. 직접 SQL로 데이터나 대상 설정을 바꾸는 작업은 애플리케이션 잠금 정책을 우회한다.

## 학습

먼저 EventService.accept()를 읽고 전달 저장이 실패할 때 이벤트 INSERT도 취소되는 이유를 설명해본다.
작은 실습: 같은 JSON을 두 번 보내 202→200을 확인한 뒤 data만 바꿔 409가 되는지 확인한다.
다음은 실제 전달 worker를 설계하되 외부 HTTP를 DB 트랜잭션 밖에서 실행해야 하는 이유를 다룬다.

## 별도 코드 검토

트랜잭션·중복 처리·대상 고정에서 차단 이슈는 없었다. 검토 중 Jackson 기본 숫자 1000자·키 50000자 제한이 본문 한도보다 작다는 문제를 확인했다. 1001자리 정수와 51000자 객체 키의 허용·재접수·숫자 변경 충돌 테스트가 먼저 실패하는 것을 확인한 뒤, 토큰 한도를 65536으로 조정했다. 전체 47개 테스트가 통과했다.
