# FlowHook pi 개발 하네스

## 적용한 구성

- 설치된 pi 0.99.2 API를 기준으로 프로젝트 전용 확장을 작성했다.
- 기존 전역 인증·모델·자동 전환 설정은 수정하지 않았다.
- 기존 `pi-auto-fallback`, `pi-mcp-adapter`는 유지했다. 추가 외부 패키지는 설치하지 않았다.
- `.pi/extensions/flowhook.ts`: 작업 선택, 범위 확인, 검증 도구, 최대 두 번의 자동 수정 요청.
- `.pi/harness/core.mjs`: Java 21 빌드·테스트·실제 HTTP 확인, 파일 변경 기록.
- `.pi/tasks/001-health-api.json`: 첫 작업 정의.
- `AGENTS.md`: 프로젝트 개발·학습 지침.
- `.pi/prompts/fh-learn.md`: 구현을 설명하고 직접 해볼 과제를 제공하는 프롬프트.
- `.pi/settings.json`: 검색 도구 추가. 모델 선택은 기존 설정을 따른다.

## 시작하기

FlowHook 디렉터리에서 pi를 실행한다. 이미 열려 있다면 `/reload`로 새 설정을 읽는다.
프로젝트 신뢰 안내가 나오면 내용을 확인한다. 전역 신뢰 설정은 변경하지 않았다.

```text
/fh-task 001
```

이 명령부터 모델 호출과 실제 작업이 시작된다. Java 21 Spring Boot 골격과 `GET /api/health` 초안은 작성되어 있다.
작업 001은 기존 코드를 유지하면서 남은 테스트 작성과 검증을 마무리한다. 데이터베이스 연동과 웹훅 기능은 후속 작업이다.

| 명령 | 역할 |
| --- | --- |
| `/fh-task` | 준비된 작업 목록 |
| `/fh-task 001` | 첫 작업 시작 또는 새 실행으로 재시작 |
| `/fh-check` | 현재 코드의 검증 실행, 모델 호출 없음 |
| `/fh-status` | 마지막 검증 상태 확인, 모델 호출 없음 |
| `/fh-stop` | 자동 작업과 진행 중인 검증 중단, 작성 파일 유지 |
| `/fh-learn` | 코드 설명·이해 확인·작은 연습 과제, 모델 호출 있음 |

## 검증과 수정 흐름

1. 작업 시작 시 파일 상태를 기록한다.
2. 허용 경로에서 구현한다. 첫 작업은 `backend/**`, `docs/progress/001-health-api.md`다.
3. Java 21 확인 → Gradle clean assemble → 테스트 재실행 → 실행된 JUnit 테스트 존재 확인 → JAR를 실행해 HTTP 상태와 응답 확인.
4. 검증 도중 코드가 바뀌었거나 작업 범위 밖 파일이 바뀌면 통과하지 않는다.
5. 실패 시 최대 두 번의 자동 수정 요청을 추가한다. 검증 실행은 한 작업 실행당 최대 세 번이다.
6. 통과 후 코드가 변경되면 `/fh-status`에 `stale`로 표시한다.

macOS에서는 검증 프로세스에만 설치된 Java 21을 지정한다. 시스템 기본 Java는 바꾸지 않는다.
검증 로그는 `.pi/runs/`에 저장하며 Git 추적에서 제외했다. 상태는 pi 세션별로 관리된다.
작업 재시작은 현재 파일을 새 기준으로 삼으므로 이전 실패의 범위 변경을 먼저 검토한다.

## 적용 범위와 현재 상태

설정과 확장 파일을 작성한 상태다. 실제 pi 세션 로딩과 모델 호출은 아직 실행하지 않았다.
백엔드 기본 골격과 상태 API 초안은 작성했고 로컬 assemble은 성공했다. 이후 전달 대상 등록·조회 API와 테스트 12개를 추가했다. 상태 API 작업 001의 JAR 기동 확인은 미완료다. 최신 기능은 `backend/README.md`를 따른다.
첫 실행에서 확장 로딩 오류가 표시되면 오류 내용을 확인한 뒤 진행한다.

직접 `write`/`edit` 호출은 허용 경로를 확인하지만, 셸 명령 전체를 격리하는 보안 샌드박스는 아니다.
파일 비교 역시 실행 후 남은 변경을 확인하며, 빌드 산출물과 외부 디렉터리의 모든 부작용을 추적하지 않는다.
기존 자동 전환 확장은 도구가 이미 실행된 요청을 자동 재실행하지 않도록 설정돼 있다.
실제 사용량 소진·다음 모델 전환은 시험하지 않았다.

PASS는 자동 검사 결과다. 코드 품질, 요구사항 전체 충족, 본인의 이해는 별도로 검토한다.
